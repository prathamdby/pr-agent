# Context glossary

Product terms used across code, prompts, and docs.

- **Webhook delivery**. Signed GitHub event request saved before intake responds.
- **PR conversation**. Main pull request discussion timeline.
- **Inline review thread**. Review comment thread anchored to a diff line range.
- **PR-surface I/O**. GitHub reads and writes performed around a pull request.
- **Slash command**. New comment starting with a slash command token.
- **Command issuer**. GitHub user posting a slash command or bot mention.
- **Commenter**. Comment author with server-preserved identity and association.
- **Authorized maintainer decision**. Allowed human reply supporting finding dismissal.
- **Reply target**. Conversation or inline thread where a command reply posts.
- **Draft pull request**. Draft pull request receiving normal automation.
- **Acknowledgement reaction**. Reaction showing queued, succeeded, or failed work.
- **Work run**. Durable row owning admission, retries, cancellation, and status.
- **Work run attempt**. Counted admission with its own identity and durable agent task.
- **Dispatcher**. In-process loop claiming due work runs and starting their attempts.
- **Harness**. Durable agent runtime owning conversations and tasks.
- **Phase A boot**. Paused read-only recovery pass before agents resume.
- **Phase B boot**. Mark aborts, resume the harness, then start dispatch and intake.
- **Trace**. Best-effort span tree recorded for attempt analysis.
- **PR execution mutex**. In-process per-pull-request lock serializing feature execution.
- **Description run**. Work item generating and merging the pull request description.
- **Description writing policy**. Diff rule setting description scale, map mode, and depth.
- **Body scale**. Description size tier governing summary length and detail.
- **Review map**. Ordered list of changed files for reviewers to inspect first.
- **Map mode**. Policy choice omitting or publishing the review map.
- **Description agent block**. Marked pull request body section owned by description runs.
- **Triage run**. Slash run re-checking findings, pushing fixes, and reporting verdicts.
- **Triage verdict**. Finding outcome of fixed, already resolved, skipped, or dismissed.
- **Verification run**. Read-only run re-checking open findings on the latest head.
- **Verification stub**. Marked bot thread reply edited across verification runs.
- **Finding objection**. Human reply posted after the root bot finding comment.
- **Objection answer**. Marked bot reply answering one finding objection.
- **Verification failure signal**. Durable head record prompting CI retry guidance.
- **Triage report comment**. Conversation comment summarizing triage commits and verdicts.
- **Triage preview**. Dry-run triage rendering proposed diffs without pushing.
- **Triage bulk apply**. Triage run committing and pushing approved preview hunks.
- **Writable PR checkout**. Isolated full Git clone where triage commits and pushes fixes.
- **Local PR workspace**. Temporary head checkout paired with cached diff metadata.
- **Code Mode**. Sandboxed JavaScript cell exposing governed workspace tools.
- **PR repository view cache**. Reference-counted checkout cache shared per head commit.
- **Approval-gated review**. Mode holding untrusted fork pull requests until approved.
- **Awaiting approval**. Durable record and notice for an untrusted pull request.
- **Orchestrated review run**. Full review running recon, specialists, judgment, and summary.
- **Review orchestrator**. Session running recon, briefs, judgment, and publication.
- **Specialist**. Parallel investigator for correctness, security, quality, or tests.
- **Specialist brief**. Recon handoff carrying intent, risks, file map, and focus.
- **Risk map**. Recon hypotheses steering specialist focus without authority.
- **Specialist report**. Candidate findings submitted by a specialist as untrusted evidence.
- **Review task checkpoint**. Durable orchestrator state letting restarts skip finished phases.
- **Causal-publication contract**. Bar requiring an evidenced defect, trigger, impact, and fix.
- **Thread batch**. Incremental comment review publishing judged inline findings.
- **Specialist tick**. Progress-comment edit updating a settled specialist row.
- **Agent session**. Multi-turn model conversation inside one work run attempt.
- **Trusted context**. Server-owned facts and base policy outside untrusted wrappers.
- **Untrusted context**. Wrapped repository, pull request, or tool text without authority.
- **Feature agent**. Shared submit-and-repair loop for feature model sessions.
- **Pi session seam**. Runtime boundary for creating and driving model sessions.
- **PR surface seam**. Boundary for GitHub pull request reads and mutations.
- **Publish intent**. Pre-mutation record fencing one GitHub write against duplicate or stale sends.
- **Operation-intent marker**. Hidden bot comment marker letting an empty store find earlier writes.
- **Review superseding**. Replacing active automatic reviews when a newer push arrives.
- **Review admission state**. Ordered close and reopen record gating review intake.
- **Review payload**. Validated structured summary fields emitted by the orchestrator.
- **Review progress comment**. Single review comment updated from queued stub to summary.
- **Own verdict**. Review check run and optional status closed from finding state.
- **Head CI state**. Durable external check snapshot stored per head commit.
- **Agent fix prompt**. Copy-paste aggregate repair prompt on the review summary.
- **Finding fix prompt**. Copy-paste repair prompt inside an inline finding thread.
- **Suggestion patch**. Optional GitHub suggestion block for a local mechanical fix.
- **Review summary comment**. Completed review comment with gates, findings, and fix prompt.
- **Duplicate finding**. Open bot thread proven to repeat another open finding.
- **Review action line**. Opening summary note covering findings, CI, and coverage.
- **Review size**. Synthesis t-shirt label describing pull request change magnitude.
- **Mergeability**. Synthesis line describing how easy a change is to revert.
- **Blast Radius**. Synthesis line describing how far a defect could spread.
- **Finding confidence**. Reviewer certainty rating shown beside finding severity.
- **CI summary**. External check gate row rendered from head CI state.
- **Prose contract**. Changed doc or rule file defining executable repository behavior.
- **Truncated change set**. Changed-file list cut at cap with truncation metadata.
- **Ask run**. Read-only work run answering a code question.
- **Ask admission**. Transactional gate deduplicating mentions and enforcing quotas.
- **Code anchor**. Diff path, range, and hunk attached to an inline ask comment.
- **Review failure notice**. Neutral comment replacing an unpublished stub on failure.
- **Summary-only finding**. Validated finding shown in the summary without a diff anchor.
- **Public-output sanitizer**. Outbound filter redacting secret-shaped text before publish.
- **Ask failure reply**. Idempotent fallback reply posted when an ask fails unanswered.
- **Ask meta refusal**. Static refusal posted without a model call on internals probes.
- **Lightweight review completion**. Fast automatic completion finishing without model calls.
- **Trivial change exemption**. Rule allowing fast completion on untruncated docs changes.
- **Finding ID**. Server-minted marker identifier tracking a finding on GitHub.
- **Finding inventory**. Open and resolved bot findings rebuilt from GitHub state.
- **Prior inline review feedback**. Earlier bot threads loaded with maintainer trust.
- **Repo policy rules**. Base-branch rule files steering review and binding footers.
- **Agent instruction files**. Root base-branch instruction files loaded with policy rules.
- **Policy suggestion**. Drafted policy snippet offered when a maintainer dismisses a finding.
- **Feature**. User-facing switch setting a surface to off, manual, auto, or approval.
- **Config slice**. Focused subset of validated settings passed to a module.
- **Evidence ledger**. Per-run log of governed reads authorizing cited paths and lines.
